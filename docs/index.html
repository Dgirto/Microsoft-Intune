¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic gestionar dispositivos en Microsoft Intune vía Microsoft Graph: listar dispositivos administrados, consultar el estado de cumplimiento de un dispositivo, y disparar una sincronización remota.

Este conector puede disparar una acción real sync_device dispara una sincronización real del dispositivo del usuario final con el servicio de Intune. list_devices y get_compliance son de solo lectura.
OperaciónQué hace
intune.list_devicesLista los dispositivos administrados por Intune
intune.get_complianceConsulta el estado de cumplimiento de un dispositivo
intune.sync_deviceDispara una sincronización remota del dispositivo

Prerrequisitos

  • Un tenant de Microsoft Intune con al menos un dispositivo inscrito.
  • Acceso a Azure Active Directory para registrar una aplicación (Service Principal) y otorgar consentimiento de administrador.

Configuración en el fabricante

  1. Registra una aplicación (Service Principal) dedicada.

    En Azure AD → App registrations → New registration. Generá un Client Secret en "Certificates & secrets".

  2. Otorgá el permiso de aplicación necesario en Microsoft Graph.

    API permissions → Add a permission → Microsoft Graph → Application permissions → "DeviceManagementManagedDevices.ReadWrite.All". Luego pulsá "Grant admin consent".

  3. Anotá los identificadores necesarios.

    Tenant ID, Client ID y Client Secret.

Permisos requeridos

PermisoPara qué sirve
DeviceManagementManagedDevices.ReadWrite.AllListar dispositivos, consultar cumplimiento y disparar sincronización
Nota No se otorgan permisos de administración de políticas de configuración ni de cumplimiento (DeviceManagementConfiguration.*, DeviceManagementServiceConfig.*).

Configuración en Ruvic

Entrá a Settings → Conectores, buscá Microsoft Intune y pulsá Configurar. Completá Tenant ID, Client ID y Client Secret.

Probar conexión — la plataforma listará dispositivos para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Listame los dispositivos de Intune."

    El agente debe devolver el listado real de dispositivos administrados.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o sin permiso suficiente"Client Secret vencido/rotado, o falta otorgar el consentimiento de administrador sobre el permiso de Graph.
"Recurso no encontrado"El device_id indicado no existe o no está inscrito en este tenant de Intune.
"No se pudo conectar a Microsoft Graph" (timeout)Restricciones de red que bloquean el acceso a graph.microsoft.com desde Ruvic.
list_devices devuelve una lista vacíaNo hay dispositivos inscritos en Intune para este tenant, o el permiso de aplicación no fue consentido correctamente.

Preguntas frecuentes y notas de seguridad

¿El agente puede cambiar políticas de configuración o cumplimiento?

No. El Service Principal solo tiene el permiso sobre dispositivos administrados; el conector no expone operaciones sobre políticas.

¿Dónde queda guardado el Client Secret?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales

Los Client Secrets de Azure AD expiran automáticamente (según lo configurado, hasta 24 meses). Generá uno nuevo antes del vencimiento y actualizalo en el formulario.

¿Qué hago si el Client Secret se compromete?

  1. Eliminá el Client Secret comprometido en Azure AD → App registrations → Certificates & secrets.
  2. Generá uno nuevo y actualizalo en el formulario.
  3. Revisá los logs de auditoría de Azure AD por actividad inesperada.
Buenas prácticas Usá un Service Principal dedicado con únicamente el permiso de dispositivos administrados; nunca uses una identidad con permisos globales de Graph; y confirmá con el usuario antes de sincronizar dispositivos en lote.
